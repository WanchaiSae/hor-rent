# DormFlow (Room Rent)

DormFlow คือเว็บแอปสำหรับจัดการงานหอพักในที่เดียว ตั้งแต่ข้อมูลห้องและผู้เช่า ไปจนถึงสัญญา ใบแจ้งหนี้ รายรับ-รายจ่าย และงานดูแลอุปกรณ์หรือซ่อมบำรุง ระบบประกอบด้วยหน้าเว็บสำหรับผู้ดูแล API สำหรับจัดการข้อมูล และ PostgreSQL สำหรับเก็บข้อมูล

## ภาพรวมการทำงาน

```text
ผู้ดูแลระบบ
    ↓
เว็บ DormFlow (Next.js)
    ↓ เรียก API ภายในเว็บ
API และกฎการตรวจสอบข้อมูล
    ↓
PostgreSQL
```

เมื่อเปิดเว็บ หน้า Dashboard จะอ่านข้อมูลจากฐานข้อมูลเพื่อสรุปสถานะห้อง ผู้เช่าปัจจุบัน รายรับ-รายจ่าย และใบแจ้งหนี้ที่ยังไม่ชำระ หากฐานข้อมูลเชื่อมต่อไม่ได้ ระบบจะแสดงสถานะการเชื่อมต่อให้เห็น

## ระบบนี้ช่วยจัดการอะไรได้บ้าง

- **ภาพรวม:** ดูข้อมูลสำคัญของหอพักและรายการธุรกรรมล่าสุด
- **หอพักและห้องพัก:** จัดการหอพัก ห้อง ชั้น ประเภทห้อง ความจุ ค่าเช่า และสถานะห้อง
- **ผู้เช่าและสัญญา:** เก็บข้อมูลผู้เช่า สัญญารายวันหรือรายเดือน และระบุผู้เช่าหนึ่งคนหรือหลายคนในสัญญา
- **ใบแจ้งหนี้:** สร้างยอดเรียกเก็บและแยกรายการ เช่น ค่าเช่า ค่าน้ำ หรือค่าไฟ พร้อมติดตามสถานะ
- **รายรับและรายจ่าย:** บันทึกธุรกรรม ผูกกับหมวดหมู่ และดูยอดตามรายการ
- **งานปฏิบัติการ:** จัดการร้านค้าและซัพพลายเออร์ อุปกรณ์ส่วนกลาง เช่น เครื่องซักผ้าและตู้กดน้ำ รวมถึงติดตามงานซ่อมบำรุง
- **ค้นหาและจัดการข้อมูล:** ค้นหารายการในหน้าปัจจุบัน และเพิ่ม แก้ไข หรือลบข้อมูลผ่านหน้าเว็บ

หน้าเว็บรองรับการใช้งานทั้งบนคอมพิวเตอร์และโทรศัพท์ ระบบนี้เป็นโครงการที่อยู่ระหว่างพัฒนา ควรตรวจสอบความพร้อมและมาตรการความปลอดภัยก่อนนำไปใช้กับข้อมูลจริง

## ความสัมพันธ์ของข้อมูล

- **หอพัก** มีห้องหลายห้อง และเป็นจุดอ้างอิงสำหรับสัญญา ใบแจ้งหนี้ และธุรกรรม
- **ห้องพัก** เชื่อมกับ **สัญญาเช่า**; สัญญาหนึ่งฉบับเชื่อมกับผู้เช่าได้หลายคนผ่านข้อมูลผู้เช่าในสัญญา
- **ใบแจ้งหนี้** ผูกกับสัญญาและมีรายการย่อยได้หลายรายการ
- **ธุรกรรม** แบ่งเป็นรายรับหรือรายจ่าย และจัดกลุ่มด้วยหมวดหมู่ทางการเงิน
- **อุปกรณ์ส่วนกลาง** สังกัดหอพักและอาจเชื่อมกับซัพพลายเออร์
- **งานซ่อมบำรุง** ใช้ติดตามปัญหาของห้องหรืออุปกรณ์ และอาจระบุซัพพลายเออร์ที่รับผิดชอบ

ฐานข้อมูลและการปรับโครงสร้างตาราง (migration) อยู่ใน `databaseDesign/` ส่วนสคริปต์ migration จะบันทึกเวอร์ชันที่ใช้แล้วใน `schema_migrations` ทำให้เรียกใช้อีกครั้งได้โดยไม่รัน migration เดิมซ้ำ

## เทคโนโลยี

- **เว็บและ API:** Next.js, React และ TypeScript
- **ฐานข้อมูล:** PostgreSQL 16
- **สภาพแวดล้อมฐานข้อมูล:** Docker Compose
- **ติดตั้งแพ็กเกจและรันสคริปต์:** Bun

## เตรียมเครื่องและเริ่มใช้งาน

ต้องติดตั้ง [Docker](https://www.docker.com/) และ [Bun](https://bun.sh/) ก่อนเริ่ม

1. เปิด Terminal ที่โฟลเดอร์หลักของโปรเจกต์ แล้วคัดลอกไฟล์ตัวอย่างตั้งค่า:

   ```powershell
   Copy-Item .env.example .env
   ```

   บน macOS หรือ Linux ใช้ `cp .env.example .env` แทน

2. เปิดไฟล์ `.env` และกำหนด `POSTGRES_PASSWORD`, `PGADMIN_DEFAULT_EMAIL` และ `PGADMIN_DEFAULT_PASSWORD` ด้วยค่าของคุณเอง จากนั้นตั้ง `DATABASE_URL` ให้ใช้ข้อมูล PostgreSQL ชุดเดียวกัน ตัวอย่าง:

   ```env
   POSTGRES_USER=postgres
   POSTGRES_PASSWORD=your-password
   POSTGRES_DB=dorm_management
   DATABASE_URL=postgresql://postgres:your-password@localhost:5432/dorm_management
   ```

   เปลี่ยน `your-password` เป็นรหัสผ่านที่กำหนดจริงในทั้งสองตำแหน่ง ห้ามนำรหัสผ่านจริงไปใส่ใน README หรือ commit ไฟล์ `.env`

3. เปิด PostgreSQL จากโฟลเดอร์หลัก:

   ```bash
   docker compose up -d postgres
   ```

4. เข้าโฟลเดอร์เว็บ ติดตั้งแพ็กเกจ สร้างหรือปรับตาราง และเริ่มเซิร์ฟเวอร์สำหรับพัฒนา:

   ```bash
   cd web
   bun install
   bun run db:migrate
   bun run dev
   ```

5. เปิดเว็บที่ [http://localhost:3000](http://localhost:3000)

การจัดการฐานข้อมูลผ่าน pgAdmin เป็นทางเลือก โดยเปิดทั้งสองบริการจากโฟลเดอร์หลักด้วย `docker compose up -d` แล้วเข้า [http://localhost:5050](http://localhost:5050)

## คำสั่งที่ใช้บ่อย

รันคำสั่งต่อไปนี้จากโฟลเดอร์ `web/`:

| คำสั่ง | ใช้ทำอะไร |
| --- | --- |
| `bun install` | ติดตั้งแพ็กเกจของเว็บ |
| `bun run db:migrate` | สร้างหรือปรับตารางฐานข้อมูลตาม migration |
| `bun run dev` | เปิดเว็บสำหรับพัฒนา |
| `bun run lint` | ตรวจรูปแบบและปัญหาโค้ดด้วย ESLint |
| `bun run build` | สร้างเวอร์ชันสำหรับนำไปเริ่มใช้งาน |
| `bun run start` | เปิดเว็บจากผลลัพธ์ที่ build แล้ว |

## API

เว็บเรียก API ภายในแอปเพื่ออ่านและจัดการข้อมูล โดยมี `GET /api/health` สำหรับตรวจสอบการเชื่อมต่อฐานข้อมูล และ API สำหรับหอพัก ห้อง ผู้เช่า สัญญา ผู้เช่าในสัญญา หมวดหมู่การเงิน รายรับ-รายจ่าย ใบแจ้งหนี้ รายการใบแจ้งหนี้ ซัพพลายเออร์ อุปกรณ์ และงานซ่อมบำรุง

- `GET /api/{resource}` อ่านรายการ และ `POST /api/{resource}` เพิ่มรายการ
- `GET /api/{resource}/{id}` อ่านรายการเดียว, `PATCH` แก้ไข และ `DELETE` ลบรายการ
- รายการแบ่งหน้าได้ด้วย `?limit=50&offset=0` โดย `limit` สูงสุด 100; ห้องกรองตามหอพักได้ด้วย `?dormitoryId=1`
- เมื่อสำเร็จ API ส่งข้อมูลไว้ใน `data`; ข้อมูลไม่ถูกต้องตอบ `400`, ไม่พบรายการตอบ `404`, ส่วนข้อมูลซ้ำหรือข้อจำกัดความสัมพันธ์ตอบ `409` พร้อมข้อความใน `error`

ตัวอย่างเพิ่มหอพัก:

```http
POST /api/dormitories
Content-Type: application/json

{"code":"A","name":"หอพัก A"}
```

## โครงสร้างโฟลเดอร์

```text
databaseDesign/
  migrations/       คำสั่ง SQL สำหรับสร้างและปรับโครงสร้างฐานข้อมูล
web/
  src/app/          หน้าเว็บและ API routes
  src/components/   ส่วนประกอบและหน้าจอของระบบ
  src/lib/          การเชื่อมต่อฐานข้อมูล API และกฎการจัดการข้อมูล
  scripts/          สคริปต์สำหรับรัน migration
docker-compose.yml  บริการ PostgreSQL และ pgAdmin
```
